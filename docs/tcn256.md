# IQL TCN256

当前正式配置使用 `training.burn_in: 255`，由配置加载器选择 `model.temporal_mode=tcn256`，Actor 网络版本 `soku_iql_tcn256_joint144_v1`，完整训练包版本 `soku_iql_bc_tcn256_joint144_v1`。不是只扩大输入而保留旧卷积。

TCN 增加到七个双卷积残差块：`dilation=[1,2,4,8,16,32,64]`，卷积核大小2、步长1，加上原因果起始卷积，感受野 `1+1+2*127=256` 帧，即当前帧和之前255帧（60FPS约4.25秒历史跨度）。特征宽度、228D 状态、当前对象分支、Joint144动作、损失定义不变。当前对象仍每侧最多3个，不增加历史对象输入。

当前配置保留 `sequence_length=32`、`n_step=30`、Neutral损失权重0.25，筛选关闭。训练每条序列共 `255+32+30=317` 帧。未来尾部帧只用于 TD 后继目标，因果卷积不会泄漏给当前决策。历史不足时训练使用有效性 mask，不能跨回合拼接。

## 从32/64帧完整 IQL 包迁移

在项目根目录手动运行，source 指向自己实际存在的旧模型：

```powershell
python scripts/migrate_tcn256.py --source outputs/iql_suika/last.pt --output outputs/iql_suika_tcn256/initial.pt --config configs/iql_suika.yaml
python scripts/train.py --config configs/iql_suika.yaml --resume outputs/iql_suika_tcn256/initial.pt
```

已有64帧模型时，将 source 改为 `outputs/iql_suika_tcn64/last.pt`。不要把旧32/64包直接传给256配置的 `--resume`。迁移复用六个网络全部旧层，新增块随机初始化；新增目标Q块复制对应onlineQ的新块。优化器、更新计数、best排名重置，固定划分与归一化保留，源步数写入迁移记录。原模型与已存在迁移目标均不会被覆盖。迁移后的策略输出不保证与原模型一致，需要重新训练和实战评估。

也可以用原 BC `--init-bc` 初始化，Actor旧层复用并明确记录扩展，新Q/V按原初始化规则生成。原BC项目不修改，旧32/64网络仍能被本项目按原spec读取。

## 实战与开销

默认新输出目录为 `outputs/iql_suika_tcn256`，实战默认加载其中 `actor_bc.pt`。本项目实战缓存按加载模型自动选择32/64/256；当前256模型必须收到256个真实连续游戏帧才推理发键，初始或断帧后约需4.3秒积累。网页所需帧数跟随模型，不再固定写32或64。

DLL的128槽队列是传输缓冲，不是模型历史窗口。Python持续取走新帧并积累独立256帧缓存，因此不需要改DLL协议；消费过慢导致128槽覆盖时仍会判定丢帧并重置，不能拿缺失数据补满窗口。原BC实战端未升级，不应加载本次新架构。

本次仍对完整历史做TCN前向，没有新增逐层卷积缓存。训练显存/计算量和实战耗时都可能明显上升，不承诺60次/秒推理；没有擅自调整batch_size、采样、N-step或精度。

已补规格、迁移严格性、因果性、窗口等价与短历史拒绝测试源码；遵照要求，未编译、运行测试、迁移模型或启动训练/游戏。
